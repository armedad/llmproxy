LLM Proxy

Local OpenAI API debugging proxy

What is LLM Proxy?

LLM Proxy sits between your apps and OpenAI's API, letting you observe and debug actual API calls. Every request and response is logged, so you can see exactly what prompts are being sent, how many tokens are used, and how long requests take.

Quick Start

  1. Start the proxy (it's already running if you're seeing this page)
  2. Configure your app to use http://localhost:8000 as the OpenAI base URL
  3. Use your app normally - requests will flow through the proxy
  4. Watch requests appear in the dashboard

Configuring Apps

OpenAI-compatible IDE or client

In your IDE or client settings, set the OpenAI base URL (or API endpoint) to http://localhost:8000. Many tools expose this under Models, API, or Provider settings.

OpenAI Python SDK

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="your-api-key"
)

OpenAI Node.js SDK

import OpenAI from 'openai';

const openai = new OpenAI({
    baseURL: 'http://localhost:8000/v1',
    apiKey: 'your-api-key'
});

curl

curl http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-4o", "messages": [{"role": "user", "content": "Hello!"}]}'

Web UI Features

  • Request list - See all proxied requests with timestamp, method, path, model, status, duration, and token count
  • Request detail - Click any request to see full headers, request body, and response body
  • Filtering - Filter by endpoint, model, or status (success/error)
  • Auto-refresh - Toggle to poll for new requests every 2 seconds
  • Copy buttons - One-click copy of request/response data

Configuration

Edit config.json to change settings:

OptionDefaultDescription
port8000Local port for the proxy
openai_base_urlhttps://api.openai.comWhere to forward requests
api_key_overridenullUse this key instead of client's
log_dir./logsWhere to store request logs
max_memory_requests1000Requests to keep in memory
log_request_bodiestrueLog request bodies to disk
log_response_bodiestrueLog response bodies to disk

Logs

Request logs are saved to logs/requests-YYYY-MM-DD.jsonl in JSON Lines format (one JSON object per line). This makes them easy to process with tools like jq. 

# View today's logs
cat logs/requests-$(date +%Y-%m-%d).jsonl | jq .

# Count requests by model
cat logs/*.jsonl | jq -r '.model' | sort | uniq -c

Security Notes

  • API keys are sanitized - Only the last 4 characters are shown in logs
  • Binds to localhost only - The proxy only accepts connections from your machine
  • No authentication - This is a local dev tool, not for production use

Supported Endpoints

The proxy forwards any /v1/* request to OpenAI, including:

  • /v1/chat/completions (streaming and non-streaming)
  • /v1/completions
  • /v1/embeddings
  • /v1/models
  • Any other OpenAI API endpoint

Troubleshooting

Port already in use

# Mac/Linux
lsof -ti:8000 | xargs kill -9

# Windows
netstat -ano | findstr :8000
taskkill /PID <pid> /F

App not connecting

Make sure your app supports custom base URLs. Some apps hardcode api.openai.com.

Streaming not working

Check that your app sends "stream": true in the request body. The proxy detects this and enables SSE passthrough.
